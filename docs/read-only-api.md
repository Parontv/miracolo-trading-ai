# Miracolo read-only Condor adapter

Miracolo connects to Condor's authenticated web API, never directly to exchange
credentials. The integration is GET-only:

- `GET /api/v1/servers` lists servers accessible to the authenticated user.
- `GET /api/v1/servers/{name}/status` reads server health.
- `GET /api/v1/servers/{name}/portfolio` reads cached portfolio balances.

The portfolio request does not set `refresh=true`, so it does not force a new
exchange fetch. The adapter never calls bot start/stop, executor, order,
credential, refresh, or any POST/PUT/PATCH/DELETE endpoint.

## Authentication configuration

Set these variables only in the backend runtime, never in browser JavaScript:

```bash
CONDOR_API_URL=http://127.0.0.1:8088
CONDOR_API_TOKEN=<Condor web-session JWT>
CONDOR_API_TIMEOUT=5
```

Condor does not issue a generic permanent API key in this flow. The bearer
value must be a Condor web-session JWT minted by its supported login flow:
local login when Condor is configured in Local mode, or token login using a
single-use login token generated by Condor's Telegram `/web` command. The
session JWT expires after 24 hours. Do not use exchange API keys here, and do
not commit the JWT to Git. Rotate/reissue it when expired.

For remote access, use a private authenticated network and HTTPS. Do not expose
Condor's local dashboard or API directly to the public Internet.

## Current boundary

The WSGI adapter and same-origin dashboard client expose health, server list,
server status, and cached portfolio reads. No trading route is exposed. This
is not yet a deployed runtime; PAPER remains mandatory and LIVE is disabled.
