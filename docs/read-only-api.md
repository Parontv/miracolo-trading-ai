# Miracolo read-only Condor adapter

Miracolo connects to Condor's authenticated web API, never directly to exchange
credentials. The integration is GET-only for data:

- \`GET /api/v1/servers\` lists servers accessible to the authenticated user.
- \`GET /api/v1/servers/{name}/status\` reads server health.
- \`GET /api/v1/servers/{name}/portfolio\` reads cached portfolio balances.

The portfolio request does not set \`refresh=true\`, so it does not force a new
exchange fetch. No bot start/stop, executor, order, credential, refresh, or
configuration mutation endpoint is called.

## Authentication configuration

Set these variables only in the backend runtime, never in browser JavaScript:

\`\`\`bash
CONDOR_API_URL=http://127.0.0.1:8088
CONDOR_AUTH_MODE=local  # only when Condor itself is configured in Local mode
CONDOR_API_TOKEN=       # used only in bearer mode
CONDOR_API_TIMEOUT=5
\`\`\`

Condor does not issue a generic permanent API key in this flow. In \`bearer\`
mode, the token must be a Condor web-session JWT minted by its supported login
flow: local login in Condor Local mode, or token login using a single-use login
token generated by Condor's Telegram \`/web\` command. The session JWT expires
after 24 hours.

For a Condor installation explicitly configured in Local mode on the same
machine, \`CONDOR_AUTH_MODE=local\` lets Miracolo obtain and renew the session
JWT through Condor's local-login endpoint. This POST is restricted in code to
the exact login endpoint and a loopback hostname (localhost, 127.0.0.1 or ::1);
the data adapter refuses remote hosts in local mode. In Telegram mode, use
\`bearer\` mode and supply a valid session JWT in the backend environment. Do not
use exchange API keys here, and do not commit JWTs to Git.

For remote access, use a private authenticated network and HTTPS. Do not expose
Condor's local dashboard or API directly to the public Internet.

## Current boundary

The WSGI adapter and same-origin dashboard client expose health, server list,
server status, and cached portfolio reads. The only permitted POST is the
loopback-only Condor local-login call when Local mode is explicitly selected;
no trading or configuration mutation route is exposed. PAPER remains mandatory
and LIVE is disabled.
