## Esito

Il deploy Cloudflare della shell Miracolo è riuscito, ma questo non equivale a un deploy di Condor o Hummingbot. La UI mostrata alla root era una dashboard Miracolo separata; Condor era soltanto un redirect opzionale. Il runtime Docker presente nel repository avvia l'API e lo scanner Miracolo, non Condor e non Hummingbot API.

## Cosa offre già Condor upstream

La revisione Condor fissata nel submodule è `2442752df1259651002034055a32d974da29a361`. Il README upstream documenta:
- dashboard web e pannello trade;
- portfolio, PnL, saldi, posizioni e ordini;
- monitoraggio bot Hummingbot;
- gestione server Hummingbot API e credenziali exchange;
- trading CEX e DEX, Gateway e liquidity pools;
- agenti AI, routine e notifiche.

Queste funzioni appartengono a Condor/Hummingbot e non vanno replicate nella shell Miracolo. Le funzioni DEX/Gateway vanno tenute disabilitate nel perimetro iniziale se non sono necessarie.

## Correzione applicata in questo branch

- Quando `CONDOR_WEB_URL` è configurato, la root `/` reindirizza alla dashboard Condor originale.
- La route `/condor` continua a usare lo stesso redirect.
- URL non HTTPS, URL con credenziali e redirect circolari vengono rifiutati.
- Se Condor non è configurato, la root mantiene la pagina diagnostica Miracolo invece di inventare uno stato di connessione.
- Aggiunti test per redirect root, fallback e blocco dei loop.

## Blocchi infrastrutturali non risolvibili con un deploy Worker

1. **Runtime persistente Condor/Hummingbot:** serve un host Linux/macOS o Windows WSL2 sempre acceso con Python 3.12, Node 22, uv e Docker secondo il setup upstream.
2. **Accesso privato:** Condor Local mode non ha login e si lega a localhost. Per il telefono usare Tailscale Serve o un reverse proxy autenticato; non esporre 8088, 8000, MQTT o database.
3. **URL pubblico/privato:** impostare il secret GitHub `CONDOR_WEB_URL` all'URL HTTPS raggiungibile dal browser e protetto. Per Tailscale Serve, il telefono deve essere sul tailnet.
4. **Alpaca:** la versione Hummingbot fissata non include un connector Alpaca. Il codice Alpaca PAPER presente in Miracolo è separato e non rende Alpaca selezionabile come exchange Condor.
5. **Execution connector:** per avere Condor/Hummingbot che esegue su Alpaca PAPER serve un connector Hummingbot dedicato e test end-to-end. Fino ad allora nessun ordine va abilitato.
6. **Cloudflare Access:** per gli endpoint Alpaca Worker occorrono la protezione Access e i secrets `ACCESS_TEAM_DOMAIN` e `ACCESS_AUD`, oltre alle chiavi Alpaca PAPER. Non condividere mai i valori in chat.

Il redirect root e i test Worker possono essere pubblicati dopo CI verde. Non distribuire o dichiarare operativo il runtime Condor/Hummingbot finché i punti infrastrutturali e di accettazione sopra non sono verificati.
